# OrcaBamDude

[![CI](https://github.com/kainpl/orca-bamdude/actions/workflows/ci.yml/badge.svg?branch=dev)](https://github.com/kainpl/orca-bamdude/actions/workflows/ci.yml)

Плагін для OrcaSlicer, що надсилає нарізані плати на ферму [BamDude](https://github.com/kainpl/bamdude) через її
HTTP API.

[English](README.md)

> **Стан: ще не випущено.** Плагін написаний і перевірений на моделі OrcaSlicer 2.5.0-rc; приймання в справжній
> OrcaSlicer ще попереду. Потрібна версія BamDude із з'єднувачем для слайсера, яку теж ще не випущено.

## Що він робить

- **Принтери ферми у списку пристроїв OrcaSlicer.** Коли вибрано агент принтера BamDude, принтери, які бачить ваш
  ключ, з'являються під іменами з BamDude — зі станом, температурами, прогресом, AMS і камерою на вкладці Device.
- **Print і Send ідуть на ферму.** Власні кнопки OrcaSlicer Print і Send відкривають вікно над копією нарізаного
  файлу, яку зробив плагін: друкувати, щойно черга дозволить, поставити в чергу із запуском вручну або лише покласти
  файл у бібліотеку BamDude; скільки копій; філамент вибирає BamDude, бере із зовнішньої котушки або зі слотів AMS,
  вибраних в OrcaSlicer.
- **За надісланим стежать.** Добу, поки OrcaSlicer відкрита: у черзі, принтер вибрано, друкується, почався перший
  шар, надруковано, не вдалося чи скасовано — кожне один раз.
- **Вкладка BamDude.** Налаштування з'єднання з покроковою перевіркою, ферма з живим моніторингом і знімком камери,
  надсилання файлу з теки експорту, історія надісланого і кнопка «Відкрити BamDude».

### Чим це відрізняється від Віртуального принтера BamDude

BamDude приймає друк і через Віртуальний принтер, що вдає з себе принтер Bambu в мережі. Цей плагін — інший шлях: він
говорить з HTTP API BamDude за API-ключем, тож працює і через reverse proxy, і поза локальною мережею ферми, а плата
потрапляє в чергу принтера чи в AutoQueue так само, як із вебінтерфейсу BamDude.

## Що потрібно

- **OrcaSlicer 2.5.0-rc** з увімкненим *Preferences → Developer → Use printer agents instead of print hosts*.
  Надсилання ввімкнене лише для цієї версії; на іншій плагін показує стан і камеру, а вкладка пояснює, чому не
  надсилає. Раніші випуски OrcaSlicer плагінів не мають зовсім — там користуйтеся Віртуальним принтером.
- **Сервер BamDude із з'єднувачем для слайсера** (`/api/v1/connector/`) — перший випуск BamDude, у якому він є.
- **API-ключ BamDude** для плагіна. Що плагін може, залежить від прав ключа: `printers:read` для списку пристроїв,
  `camera:view` для камери, `library:upload` + `library:read_all`, щоб класти файли в бібліотеку, `queue:create` +
  `library:read_all`, щоб ставити їх у чергу. Перевірка з'єднання у вкладці називає кожне право, якого бракує. Ключ
  читає кожен файл бібліотеки, який може читати його власник.

## Встановлення й оновлення

Завантажте `orca_bamdude_any.whl` з [Releases](https://github.com/kainpl/orca-bamdude/releases), звірте його з
`SHA256SUMS` випуску й установіть в OrcaSlicer: *Plugins → Install local plugin*. Оновлення — файл із тим самим
ім'ям: встановіть поверх старого, потім знову активуйте плагін і погодьтеся на його дозволи — OrcaSlicer питає про
них для кожної нової версії. Налаштування зберігаються.

### Дозволи

OrcaSlicer один раз, під час запуску плагіна, питає про те, що йому потрібно:

- **власні потоки** — щоб говорити з фермою, не затримуючи вікно OrcaSlicer;
- **читання тимчасових файлів моделей OrcaSlicer** — нарізаного файлу, який передають Print і Send;
- **локальний ретранслятор камери на 127.0.0.1** — відеоплеєр OrcaSlicer не вміє надіслати API-ключ, тож плагін
  передає йому потік ферми з вашого ж комп'ютера;
- **налаштовану вами адресу ферми** — і нічого більше;
- **читання теки експорту**, якщо ви її задали;
- **відкриття дашборда BamDude** у браузері — лише адреси вашого сервера.

Якщо відповісти **Ні**, OrcaSlicer вимкне плагін; увімкнути знову — *Plugins → Activate*. Адреси, яких стосувався той
запит, після цього не запитуються, доки ви не попросите їх у вкладці («Попросити під час наступного запуску») або не
зміните, тож одна відмова не повертається на кожному запуску. Нову адресу, збережену у вкладці, OrcaSlicer запитає під
час наступного запуску.

## Налаштування

1. Відкрийте вкладку **BamDude**, введіть адресу сервера й API-ключ і збережіть. Для сервера із самопідписаним
   сертифікатом вставте сертифікат його CA **текстом PEM** — ніколи не шляхом до файлу. Перевірку сертифіката не
   вимикають ніколи.
2. **Перевірте з'єднання** у вкладці: перевірка йде по кроках і каже, чого бракує.
3. У пресеті принтера виберіть *Printer Agent → BamDude*, потім виберіть принтер ферми на вкладці Device. Першого разу
   OrcaSlicer попросить код доступу: підійде будь-який — важить API-ключ ферми.

**API-ключ зберігається відкритим текстом** у файлі конфігурації плагінів OrcaSlicer (`orca_plugins/config.json` у
теці даних OrcaSlicer) — так OrcaSlicer зберігає налаштування будь-якого плагіна. Після збереження вкладка його не
показує, і він не йде нікуди, крім вашого сервера.

### Інша адреса для одного пресету принтера

Пресет принтера може направити плагін на іншу адресу ферми — скажімо, локальну на фермі й публічну деінде — з власним
CA. Редагується це в *Налаштування принтера → Агент принтера → вибрати BamDude ще раз → Можливості: Налаштувати… →
BamDudePrinter* (в англійському інтерфейсі: *Printer settings → Printer Agent → … → Capabilities: Configure…*);
кнопка «Скинути до глобального» («Restore to global») прибирає перевизначення. З пресету беруться лише адреса й CA: API-ключ і
заголовки проксі — завжди з вкладки, бо файли пресетів експортують і синхронізують.

### Після відновлення сервера, нової адреси чи нового ключа

Принтери плагіна належать одному серверу, його даним і одному ключу. Після відновлення BamDude з резервної копії,
зміни його адреси чи ключа OrcaSlicer на кожному старті показує «Connect … failed», доки ви знову не виберете принтер
на вкладці Device; старі записи лишаються в *My Device* — це власний список OrcaSlicer. Щоб перенести ферму на іншу
машину, користуйтеся резервним копіюванням і відновленням BamDude: побайтову копію за тією самою адресою не відрізнити
від оригіналу.

## Користування

- **Print** спершу пропонує чергу; **Send** — бібліотеку і нічого не ставить у чергу, якщо ви цього не виберете.
  Сповіщення каже, куди потрапив файл. Після Send власне повідомлення OrcaSlicer говорить про «сховище принтера» — це
  текст OrcaSlicer; файл у бібліотеці BamDude.
- **Слоти AMS, вибрані в OrcaSlicer,** можна зберегти для однієї плати, якщо поточний стан принтера їх ще показує;
  інакше вікно про це скаже, і вибере BamDude.
- **Скасування** в діалозі OrcaSlicer повертає керування одразу; якщо ферма вже отримала запит, плагін просить її
  зупинити те, що ще не почалося.
- **Відповідь, якої ферма не дала вчасно,** показується як «ще не підтверджено», а не як помилка, і перевіряється знову
  під час запуску OrcaSlicer. Перевірте її в історії вкладки, а не надсилайте ту саму плату вдруге.
- **Тека експорту** (необов'язково): вкладка показує нарізані файли 3MF у ній і надсилає вибраний на принтер чи в
  AutoQueue.
- **Живий моніторинг** у вкладці читає всю ферму, лише поки ввімкнений. На старті він вимкнений і вимикається сам за
  десять хвилин після вашої останньої дії у вкладці; кожна дія починає ці десять хвилин знову. «Оновити» читає один
  раз.
- **Сповіщення** з'являються на вкладках Prepare і Preview OrcaSlicer; історія у вкладці BamDude показує останній
  крок кожного надсилання.

## Розробка

Python 3.12 (його вбудовує OrcaSlicer) і лише стандартна бібліотека; тестам потрібен `pytest` (і Node.js для власного
скрипта сторінок — без нього ці тести пропускаються).

```bash
pip install -r requirements-dev.txt
python -m pytest
ruff check . && ruff format --check .
python tools/build_wheel.py      # dist/orca_bamdude_any.whl
```

Тести не виходять у мережу далі `127.0.0.1` і не потребують ні OrcaSlicer, ні сервера BamDude. Робота потрапляє в
`dev`; `main` містить випущений код. Як долучитися і як випускаються релізи: [CONTRIBUTING.md](CONTRIBUTING.md)
(англійською).
