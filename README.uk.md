# OrcaBamDude

[![CI](https://github.com/kainpl/orca-bamdude/actions/workflows/ci.yml/badge.svg?branch=dev)](https://github.com/kainpl/orca-bamdude/actions/workflows/ci.yml)

Плагін для OrcaSlicer, що надсилає нарізані плати на ферму [BamDude](https://github.com/kainpl/bamdude) через її
HTTP API.

[English](README.md)

> **Стан: у розробці, не випущено.** Ядро, незалежне від слайсера (налаштування з'єднання, HTTP-клієнт, перевірка
> нарізаного 3MF, локальна копія файлу, що надсилається, журнал операцій, relay камери й планувальник опитування),
> написане й покрите тестами. Частина для OrcaSlicer — агент принтера за власними кнопками Orca Print/Send, вкладка
> BamDude і плеєр камери — ще не написана.
> Wheel для встановлення поки немає.

## Навіщо

BamDude уже приймає друк зі слайсера через свій Віртуальний принтер. Цей плагін — другий шлях: він говорить з HTTP
API BamDude за API-ключем, а не вдає принтер у мережі, тож працює і через reverse proxy, і поза локальною мережею
ферми. Плата, яку він надсилає, потрапляє в чергу одного принтера або в AutoQueue BamDude — так само, як ніби її
поставили в чергу з вебінтерфейсу BamDude.

## Що потрібно

- **OrcaSlicer 2.5.0-rc** або новіший, з увімкненим *Preferences → Developer → Use printer agents instead of print
  hosts*. Старіші випуски OrcaSlicer плагінів не підтримують; там користуйтеся Віртуальним принтером BamDude.
- **Сервер BamDude із з'єднувачем для слайсера** (`/api/v1/connector/`). У випущеній версії BamDude з'єднувача ще
  немає.
- **API-ключ BamDude** для плагіна. Йому потрібен доступ до черги, щоб надсилати друк, і до бібліотеки, щоб
  вивантажити файл. API-ключі BamDude поки не можна обмежити частиною бібліотеки, тож ключ читає кожен файл
  бібліотеки, який може читати його власник.

## Як він поводиться

- **Один сервер.** Плагін звертається лише за адресою, яку ви ввели. TLS перевіряється завжди; сервер із
  самопідписаним сертифікатом довіряється через вказаний вами CA-файл, а не вимкненням перевірки. Переадресацій
  плагін не виконує.
- **Без дублікатів.** Кожне надсилання — операція з ідентифікатором, який плагін записує до першого запиту. Якщо
  відповідь загубилася, повторне надсилання поверне те, що сервер зробив першого разу, а не поставить роботу в
  чергу вдруге.
- **Ті самі байти, що нарізані.** Плагін один раз копіює нарізаний файл у свою теку, рахує хеш, перевіряє його і
  вивантажує саме цю копію, тож файл, який слайсер тим часом перезаписав, до принтера не дійде.
- **Помилки вашою мовою.** Відмови BamDude приходять уже перекладеними сервером; сиру сторінку сервера плагін не
  показує.

## Встановлення

Коли версію буде випущено, завантажте `orca_bamdude_any.whl` з
[Releases](https://github.com/kainpl/orca-bamdude/releases) (звірте з `SHA256SUMS` релізу) і встановіть в OrcaSlicer:
*Plugins → Install local plugin*. Оновлення — так само: ім'я файлу не змінюється, тож OrcaSlicer зберігає
налаштування плагіна.

## Розробка

Python 3.12 (його вбудовує OrcaSlicer) і лише стандартна бібліотека; тестам потрібен `pytest`.

```bash
pip install -r requirements-dev.txt
python -m pytest
ruff check . && ruff format --check .
python tools/build_wheel.py      # dist/orca_bamdude_any.whl
```

Тести не виходять у мережу далі `127.0.0.1` і не потребують ні OrcaSlicer, ні сервера BamDude. Робота потрапляє в
`dev`; `main` містить випущений код. Як долучитися і як випускаються релізи: [CONTRIBUTING.md](CONTRIBUTING.md)
(англійською).
